# 设计：小岛成就（可选激励）

生成时间：2026-11-14
状态：v1 已实现（15 个学习成就 + 2 个诗歌试点成就）；诗歌成就随「诗岛」继续扩展
模式：Builder
范围：`stats.db` + 今日页 + 结算页 + 家长页

## 问题陈述

朋友希望增加积分。积分能提供每日反馈，但容易变成货币；成就徽章可能更适合这个 app：奖励真实学习行为，不制造可兑换的「钱」。

## 判断

**优先做成就，不先做积分。**

- 成就从真实学习数据推导，不需要积分流水、商城、兑换。
- 成就奖励坚持、广度、勇气、探索，不奖励正确率、速度或自评标签。
- 成就永久，不扣、不排名、不比较。
- 如果孩子确实需要「每天看到数字变大」，再加一个很轻的「完成星」，但不做商城。

## 成就 vs 积分

| | 小岛星星（积分） | 成就徽章 |
| --- | --- | --- |
| 反馈频率 | 每天 | 里程碑 |
| 主要作用 | 开始、坚持 | 自豪感、长期目标 |
| 风险 | 货币化、讨价还价、刷分 | 徽章太多、远处目标 |
| 数据 | 需要 `points_ledger` | 可从现有表推导 + `badge_unlocks` |
| 建议 | 第二版，默认关 | 第一版，默认开 |

## 设计原则

1. 只奖真实学习行为：完成、坚持、学会、探索。
2. 不奖正确率、速度、自评「认识」；不扣分；不排名；不隐藏成就。
3. 12–15 个，分 5 类；每个都有进度，锁定的也告诉孩子怎么解锁。
4. 解锁发生在结算页，不在答题中间弹窗。
5. 成就永久；连续天数断了也不会失去已得徽章。
6. 家长开关；关闭时隐藏孩子端，数据保留。

### 让孩子快乐的六个原则

1. **奖励行动，不奖励天赋**：读完、跟读、发现、坚持，而不是「全对」「最快」。
2. **具体反馈**：说「你找到了 3 个颜色词」，不说「真棒」。
3. **不扣、不排名、不比较**：没有排行榜，没有「别人家孩子」。
4. **允许暂停**：断了不显示红色警告；回来给一枚「欢迎回来」印章。
5. **给孩子选择**：今天读月亮还是动物？自己选的诗更愿意读。
6. **家庭连接**：家长盖章、读给家人听、一起背；快乐很大一部分来自被看见。

## 怎么展示

- **今日页**：一个紧凑的「成就墙 5 / 15」卡片，显示 3 个最近获得的印章，点进去看全部。
- **成就页**：`#/achievements`，按类别分组；已获得在前，未获得显示进度（如 32 / 50）；再显示「下一个成就」。
- **结算页**：如果解锁新成就，弹出一枚大印章 + 标题 + 一句话，点「收下」关闭。一次只弹一个，多个成就合并成「一次点亮 3 个」。
- **家长页**：新增「小岛成就」面板，含开关、完整成就墙、解锁日期；现有「部首徽章」改名为「部首徽章（家长统计）」，避免和新成就混淆。
- **视觉**：用红色印章 + 单字（岸 / 灯 / 船 / 园 / 塔 / 火 / 勇 / 补 / 题 / 部），纸色底，已获得金色描边；锁定状态灰一些，但不要看起来像惩罚。尊重「减少动效」设置。

## 家长开关

- `achievements_enabled`，默认 `true`。
- 关闭时：今日页成就卡、结算页成就弹窗、成就页入口都隐藏；已获得的数据保留；家长页仍可看到成就进度。
- 重新开启：之前获得的成就直接显示；未看过的成就合并成一次「你已经点亮 N 个成就」，不要连弹 N 个。
- 成就不是货币，不兑换实物，不做排行榜。
- 「清空学习进度」同时清空成就；另提供「只清空成就」（可选）。

## 数据与接口草案

- `badge_unlocks(badge_id TEXT PRIMARY KEY, unlocked_at TEXT NOT NULL, local_date TEXT NOT NULL, seen INTEGER NOT NULL DEFAULT 0, meta_json TEXT)`
- 成就定义放在 `server/achievements.py`，每个成就一个 `id`、标题、描述、类别、印章字、目标值、计算 SQL / 函数。
- `GET /api/achievements` → `enabled`、`badges`（含 `earned`、`unlocked_at`、`progress`、`target`）、`unseen`、`next`
- `POST /api/achievements/seen` → 标记已展示，避免重复弹窗
- `POST /api/achievements/reset` → 只清成就（可选）
- `settings.achievements_enabled`（bool，默认 true）
- `sessions.completed`（bool，默认 false）：`PATCH /api/sessions/{id}` body `{ completed: true }`，用于「初次上岸」
- 服务端计算并写入 `badge_unlocks`；客户端只展示，不自己判断
- 首次对已有数据启用时，已满足的成就静默补录；之后只弹新解锁的

## 必须先修的一个统计问题

现在「连续天数」只算普通 `attempts`，认字复习不算学习日。如果做坚持类成就，要先把 `attempts` 和 `recognition_attempts` 的日期合并计算。否则只做认字的孩子永远拿不到「三日小火苗」。

## 边界

- 不奖「全对」、不奖「答得快」、不奖「自评认识」；避免孩子回避难字或污染自评。
- 连续天数断了，已得徽章不收回；进度显示当前连续天数即可。
- 一次解锁多个成就时，不要连弹多个弹窗；合并展示。
- 已有用户可能一次补录很多成就；用「你已经点亮 N 个成就」汇总，不逐个弹。
- 关闭成就后不再弹窗；重新开启不补发新的弹窗轰炸。
- 成就只存在 `stats.db`，备份学习记录时一起备份。

## 成功标准

- 孩子能说出一个自己正在努力的成就。
- 家长 10 秒内能找到开关。
- 连续使用 1 周，成就进度与学习记录一致，没有重复解锁。
- 关闭后界面干净，重新开启数据还在。
- 孩子没有因为成就而只做简单的字、或谎报「认识」。

## 开放问题

1. 朋友的孩子更喜欢收集徽章，还是每天要看到一个数字变大？前者做成就就够；后者再加一个轻量「完成星」。
2. 成就默认开还是默认关？我倾向成就默认开、积分默认关。
3. 结算页现有 1–3 颗按正确率给的星，要不要以后改成完成奖励？这次先不动，成就用印章视觉区分。
